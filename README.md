# Smena

Закрытие смены администратором ПК-клуба и учёт денег вокруг этого: сейф, банк, ЗП, расходы.

- Бизнес-правила — [docs/PLAN.md](docs/PLAN.md).
- Устройство и этапы — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что готово

- Этап 1 — каркас: решение, PostgreSQL в docker-compose, сервер с проверкой здоровья, настройки клуба, тесты на настоящей базе.
- Этап 2 — учёт: счета, справочники, операции → транзакции → проводки, балансы, отмена, сотрудники со своими счетами. База сама проверяет баланс каждой транзакции и каскадно удаляет сверху вниз. API пока нет — оно появляется с операциями на этапах 3–4.

- Этап 3 — смена: расчёт в ядре (одни формулы для предпросмотра и закрытия), проводки смены, системные категории, токен устройства кассы, API кассы.

- Этап 4 — операции кассы: аванс и выплата ЗП из сейфа, приход и расход сейфа по категориям, ожидаемые зачисления в банк (безнал смены и инкассация) с подтверждением и комиссией, остаток банка двумя числами.

- Этап 5 — клиент на кассе: интерфейс (`web/cashier`, перенесён из старого Smena.Client) раздаётся сервером по адресу `/cashier/`; программа на кассе (`src/Smena.Client`) — окно WebView2, которое открывает этот адрес и передаёт токен устройства. Фото и пересчёт склада появятся на своих этапах.

- Этап 6 — outbox и Telegram: сообщения (отчёт смены, сейф, расходы, личные темы ЗП) ставятся в очередь в одной транзакции базы с операцией и отправляются фоновым процессом через прокси, с повторами и сохранением порядка.

- Этап 7 — панель root (`web/panel`, адрес `/panel/`): вход по паролю, обзор, журнал операций с отменой, зачисления в банк, сотрудники (выплаты, штрафы, премии), банк и стартовые остатки, инвентаризация, категории, настройки клуба, устройства кассы. Не сделаны: сверка банка с выпиской, просмотр очереди Telegram, отчёты P&L и ДДС.

- Этап 8 — фото: касса показывает QR, администратор с телефона открывает страницу загрузки и снимает; сервер проверяет и пережимает снимки, при закрытии смены привязывает их к ней, показывает в панели и отправляет альбомом в Telegram.

- Этап 9 — кабинет сотрудника (`web/miniapp`, адрес `/miniapp/`): Telegram MiniApp, в котором сотрудник видит свой баланс и историю начислений, выплат и удержаний. Вход — по подписи Telegram, без паролей.

Дальше — этап 10: пересчёт склада.

## Кабинет сотрудника (MiniApp)

```bash
cd web/miniapp && npm install && npm run build    # сборка в src/Smena.Server/wwwroot/miniapp
```

- **Как сотрудник попадает в кабинет.** В BotFather у бота задаётся кнопка меню (Menu Button) с адресом `https://<адрес сервера>/miniapp/`. Сотрудник открывает чат с ботом и нажимает её.
- **Кто он.** Telegram передаёт странице подписанную строку; сервер проверяет подпись токеном бота (`Telegram__BotToken`) и ищет активного сотрудника с таким Telegram ID (задаётся в панели при добавлении сотрудника). Чужой или отключённый сотрудник получает отказ. Подпись действует 24 часа с запуска — потом кабинет нужно открыть заново.
- **Что нужно для работы.** Токен бота и публичный адрес сервера с HTTPS: Telegram открывает MiniApp только по HTTPS. Без токена кабинет выключен.
- **Что видно.** Только свои данные: баланс, ставка, история движений по своему счёту (без отменённых операций). Сумма истории всегда равна балансу.
- Страница не загружает ничего со сторонних адресов (в том числе скрипт Telegram): всё нужное Telegram передаёт в адресе страницы.

API кабинета — заголовок `Authorization: tma <initData>`:

| Метод | Назначение |
|---|---|
| `GET /api/me` | имя, ставка, баланс |
| `GET /api/me/operations?take=&before=` | история от новых к старым; `before` — `id` последней полученной строки |

## Фото к смене

1. На кассе, в отчёте смены, — «Показать QR для фото». Появляется код и счётчик «0 из 3».
2. Администратор наводит камеру телефона на код, на открывшейся странице снимает или выбирает фото. Счётчик на кассе обновляется сам.
3. Когда фото достаточно, смену можно закрыть: фото привязываются к ней той же транзакцией базы.

- Минимум фото и допустимая давность снимка — настройки клуба в панели (по умолчанию 3 фото и 5 часов). Максимум — 10 фото на смену.
- Тот же файл второй раз не принимается — ни в эту смену, ни в следующие.
- Снимок старше допустимого или без времени съёмки принимается, но помечается в отчёте и в панели.
- «Сбросить фото» и показ нового QR удаляют фото, которые ещё не отправлены с отчётом.
- Принимаются JPEG, PNG, WebP и HEIC до 25 МБ; хранится уменьшенный JPEG (длинная сторона 1600 px) без метаданных.

Телефон должен видеть сервер по сети. Если касса открывает сервер по адресу, недоступному телефону (например, `localhost`), задайте `Photos__PublicBaseUrl` — адрес сервера в сети клуба.

## Панель root

```bash
cd web/panel && npm install && npm run build    # сборка в src/Smena.Server/wwwroot/panel
```

Адрес — `/panel/`. Пользователь `root` создаётся при первом старте из настройки `Root:BootstrapPassword` (переменная среды `Root__BootstrapPassword`, от 10 символов); в Development пароль задан в `appsettings.Development.json`. После пяти неверных паролей подряд вход блокируется на 5 минут. Пароль меняется в панели на вкладке «Настройки».

Правила отмены:

- отменяется операция целиком, с обязательной причиной;
- из смен отменить можно только последнюю;
- операцию, по которой подтверждено зачисление в банк, сначала нужно «расподтвердить» на вкладке зачислений;
- комиссия банка отменяется только вместе с подтверждением зачисления.

## Telegram

Telegram необязателен и никогда не задерживает операции: смена закрывается, даже если он недоступен, а сообщения ждут в таблице `outbox_messages`.

- **Токен и прокси** — переменные среды `Telegram__BotToken` и `Telegram__ProxyUri` (например, `socks5://192.168.88.92:10801`). Без токена отправка выключена.
- **Чаты и темы** — в таблице `club_settings` (позже — в панели): `telegram_chat_id` с темами `telegram_reports_thread_id`, `telegram_safe_thread_id`, `telegram_expenses_thread_id` и `telegram_salary_chat_id`. Личная тема сотрудника — `employees.salary_thread_id`. Не задано — сообщения этого вида не создаются.
- **Повторы**: при сбое сети или прокси — через 10 с, 20 с, 40 с… до 15 минут, без ограничения числа попыток; порядок сообщений сохраняется. Если Telegram отказал по существу (нет чата или темы), сообщение помечается как отклонённое и остальных не задерживает.

## Интерфейс кассы

```bash
# сборка в src/Smena.Server/wwwroot/cashier — после неё сервер раздаёт интерфейс сам
cd web/cashier && npm install && npm run build

# разработка: интерфейс с Vite (http://localhost:5173/cashier/), API — с локального сервера
cd web/cashier && npm run dev
```

В браузере интерфейс один раз спрашивает токен устройства. Программа на кассе (`src/Smena.Client`) спрашивает адрес сервера и токен при первом запуске и хранит их в профиле Windows (токен зашифрован). Собирается она и в WSL, запускается только в Windows:

```bash
dotnet publish src/Smena.Client -c Release -r win-x64 --self-contained false
```

## API кассы

Все адреса требуют заголовок `Authorization: Bearer <токен устройства>`.

| Метод | Назначение |
|---|---|
| `GET /api/config` | размен и лимиты смены |
| `GET /api/employees` | активные сотрудники с балансами |
| `GET /api/safe` | баланс сейфа |
| `POST /api/shifts/calc` | предпросмотр расчёта, ничего не пишет |
| `POST /api/shifts` | закрыть смену; при проблемах в расчёте — 422 и ничего не записано |
| `GET /api/categories?kind=safeIncome\|safeExpense` | категории, доступные администратору для прихода или расхода сейфа |
| `POST /api/payouts` | аванс или выплата ЗП из сейфа: не больше баланса сотрудника и не больше сейфа |
| `POST /api/safe/income` | приход в сейф по категории |
| `POST /api/safe/expense` | расход из сейфа по категории; инкассация создаёт ожидаемое зачисление в банк |
| `POST /api/photo-sessions` | новая сессия фото: ссылка для QR; прежние неотправленные фото стираются |
| `GET /api/photo-sessions/{id}` | сколько фото загружено; 404 — сессии больше нет |
| `DELETE /api/photo-sessions/{id}` | сбросить фото |

В запросе закрытия смены и предпросмотра поле `photoSessionId` — сессия, фото которой прикладываются к смене.

Все `POST`, кроме предпросмотра, требуют заголовок `Idempotency-Key` с UUID запроса: повтор с тем же ключом не проводит операцию второй раз. Отказ по правилам — ответ 422 с текстом для администратора.

Подтверждение зачислений в банк (`BankReceiptService.ConfirmAsync`) уже работает, но адреса для него пока нет: это действие root, оно появится вместе с панелью.

Пока нет панели, устройство кассы создаётся при старте из настройки `Cashier:BootstrapToken` (переменная среды `Cashier__BootstrapToken`, от 32 символов). В Development токен задан в `appsettings.Development.json`. Сотрудники до появления панели заводятся прямо в базе.

## Запуск (WSL, дистрибутив `claude`)

Все команды — из корня репозитория.

```bash
# база
DOCKER_HOST=unix:///var/run/docker.sock docker compose -f deploy/docker-compose.yml up -d --wait

# сервер: http://localhost:5080, миграции применяются при старте
dotnet run --project src/Smena.Server

# проверка
curl http://localhost:5080/health/ready

# тесты (поднимают свой одноразовый PostgreSQL)
DOCKER_HOST=unix:///var/run/docker.sock dotnet test --solution Smena.slnx
```

Новая миграция:

```bash
dotnet ef migrations add <Имя> --project src/Smena.Server --output-dir Database/Migrations
```

## Переменные среды

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `Database__ConnectionString` | строка подключения к PostgreSQL | в Development — локальная база из docker-compose; иначе обязательна |
| `Database__MigrateOnStartup` | применять миграции при старте | `true` |
| `Cashier__BootstrapToken` | токен первого устройства кассы | в Development задан; иначе пусто — устройство не создаётся |
| `Root__BootstrapPassword` | пароль первого пользователя панели | в Development задан; иначе пусто — пользователь не создаётся |
| `Photos__StoragePath` | каталог с файлами фото | `data/photos` в каталоге сервера |
| `Photos__PublicBaseUrl` | адрес сервера для телефона (ссылка в QR), например `http://192.168.1.10:5080` | адрес, по которому обратилась касса |
| `Telegram__BotToken` | токен бота: отправка сообщений и проверка входа в MiniApp | пусто — отправка и MiniApp выключены |
| `Telegram__ProxyUri` | прокси для выхода к Telegram | пусто — напрямую |
| `Telegram__PollIntervalSeconds` | как часто проверять очередь | `5` |

Время в базе всегда в UTC. Часовой пояс клуба — не переменная среды, а настройка в таблице `club_settings` (по умолчанию `Europe/Moscow`); позже будет меняться в панели. Он нужен только для текста сообщений в Telegram, времени съёмки фото без пояса и границ суток в отчётах.

## Особенности этой машины

- NuGet напрямую недоступен. Для команд, которые качают пакеты (`dotnet restore`, `dotnet add package`), задать прокси на время команды: `HTTPS_PROXY=http://10.0.100.10:8080`.
- Docker Hub недоступен: образы берутся с `mirror.gcr.io`.
- Telegram напрямую недоступен (заблокирован в стране): Bot API отвечает только через SOCKS5-прокси `192.168.88.92:10801`. Через zapret-proxy на `10.0.100.10` он не открывается.
- В тестах отключён Ryuk (служебный контейнер Testcontainers): его образ есть только на Docker Hub.
